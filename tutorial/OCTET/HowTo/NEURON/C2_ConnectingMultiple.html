C.2. Connecting the PCs together

After completing exercise with axonal conduction velocity, we now have layer 5 pyramidal cell (L5PC) including the dendrite and an active axon. If you do not have it, then connect the axon (without the soma) you created in the conduction velocity exercise to the reconstructed L5PC morphology. We want to simulate a synaptic input from the axon of a presynaptic neuron to the dendrite of a post synaptic neuron.

NEURON uses an event based simulation model in for connecting cells together. Events are usually things like action potentials, as it is the events (rather than, for example, the specific voltage levels) that we need to pass or communicate between the presynaptic and the postsynaptic neurons. By using an event based model, we can dramatically reduce the amount of inter- communication because information between pre and post synaptic neurons is sent only on events. This is important in simulation time optimization and in network simulations on parallel machines.

To connect our PC axon to a post synaptic neuron, first we create a list object that will hold an arbitrary number of NetCon objects. A NetCon object is an object associated with a particular source of events (usually the voltage in a segment of the soma or an axon, where a particular change in Vm (such as when action potential is triggered) will trigger an event in the simulation. Another option is using the NetStim object which can trigger an event as defined by the user). So, let’s begin by loading the L5PC dendrite and axon code (for model you created) that can fires action potentials:

load_file(“your file name”)

 

Next, we create a post synaptic neuron (the neuron which will receive the synaptic input):

 

create target_cell
target_cell {
     L  = 30
     diam = 30
     insert pas
}

Let’s define a new location for target_cell such that it would be visible.

target_cell{
     define_shape()
     for i=0, n3d() - 1 {
          pt3dchange(i, x3d(i) + 100, y3d(i), z3d(i), diam3d(i))
     }
}

For now, the meaning of the code above is not important to us. Next we will define the object nclist by using the List() function. 

objref nclist

  

  
  
  
  
  nclist = new List()

 

A List is an object that holds a list of other objects, like an array. In this case, the object it will hold will be a synapse. We will see later how to add items to a list and change their values.

The advantage of a list (over an array) is that we don't have to specify in advance how big it will grow.

C.2.b Creating a synapse

For our first connection, we want to be able to connect the L5PC to target_cell and observe the EPSPs (Excitatory Post Synaptic Potentials) at target_cell.

In order to make the L5PC axon trigger an EPSP at target_cell we must first create a few synaptic objects. Like IClamp which was discussed in A.2, a synapse is simply an object that can be positioned anywhere on a section. For example, we can define a new array of objects for synapses that will appear in various sections. We will create 2 object references which will be used to hold information about synaptic contacts by adding following code:

maxsyn = 2
objref syn[2]

We are going to use the synapses you created at the NMODL talk given by Christian. To remind you, the synapse type name is the name of your choice which follows the POINT_PROCESS keyword in the mod file. For now use the default values for the synaptic rise and decay time.

Next, position the synapse, in the same manner IClamp is positioned, i.e. by referring to a section where we wish the synapse to be located and create the synapse there. The code below creates a synapse positioned on target_cell. The information for this synapse is stored in the syn array object, index 0 (syn[0]):

target_cell syn[0] = new MySynapse(0.5)

Rather than MySynapse  write the name of your synapse .

After saving and running the hoc file you could see the synapses by selecting Tools>>Point Processes>>Managers>>Point Group. The two cells, target_cell (the dot on the left) and the L5PC (the morphology on the right) will be side by side. Currently you only see the IClamp(0.5) point process on the L5PC. To see your synapse, select your synapse name from the Show All button. You should then see a red dot indicating that the synapse is located on target_cell.

Note: in these displays, the blue dots indicate the location of the POINT_PROCESS objects and the red color shows which point is currently selected--click on another object (on the list at the middle panel) and a corresponding point process will turn red.

If you want to change the location of the point process, click on the neuron morphology and the red dot will change its location. The exact location ( section_name(x) ) is printed above the graph.

C.2.c Using NetCon to connect and set activation trigger for synapse

Yesterday we used NetStim as a source for the synaptic event. Now we will define the source of events for this synapse to be the action potentials generated at the axon of your L5PC model. Since target_cell receives the events (i.e. the section where the synapse is located) we must append a new NetCon object to the nclist. In order to create a new NetCon object, we use the command format:

new NetCon(&source_v, synapse, threshold, delay, weight)

  • source_v is the source voltage (in our case the voltage from soma)
  • synapse is the object variable that refers to the synaptic object receiving the events (in our case syn[0])
  • threshold is the threshold which the voltage must reach for it to be considered that an action potential has occurred,
  • delay is the connection delay
  • weight is the connection weight strength at the synapse. The weight is a measurement of how strong the connection is: a strong connection would have a weight of 1 uS, a weaker connection might have a weight of 0.001 (1 nS).

So to connect L5PC axon to target_cell we add the command:

access terminal 
nclist.append(new NetCon(&v(1), syn[0], 3, 2, 0.01))

Note:

Terminal is considered here as the name of the part of the axon which is the furthest from the soma of L5PC the axon terminal. You may have given it another name.

So, initially, this command accesses section terminal which will fire action potentials in response to electrode (IClamp) stimulation. Then the nclist gets (with append) a new NetCon object that uses v(1) of section terminal as a sourceand syn[0] which we located on target_cell (see above) as a target. We use 3 mV as the threshold (i.e., when the membrane potential is above 3 mV the NetCon triggers an event), delay 2ms (corresponding to synaptic or axonal delay), and synaptic weight of 0.01.

Now, we will create a second synapse, syn[1], which is identical to syn[0] and place it on one of the dendrites of the L5PC on a section apic[11] with the following code:

apic[11] syn[1] = new MySynapse(0.5)

and we will use the new following NetCon object:

terminal nclist.append(new NetCon(&v(1), syn[1], 3, 2, 0.01))

Notice that the source (terminal potential) and the target (syn[1]) are located on the same neuron. The synapses that connect a neuron to itself are called autapses.

Run the simulation and plot the voltage at soma, terminal, target_cell and apic[11]  with different colors (you know how)

 

Can you see the:

2.      EPSP at the target_cell?

C.2.D Working with lists

How do we change the weight, threshold and delay of our NetCon after it was created? If we had declared an objref called nc, we would have been able to refer to nc.weight, nc.threshold and nc.delay. However, our NetCon objects are embedded in a list, so we can't access these properties directly.

Because we used the append command (nclist.append(obj)) to add the object specified by the object variable obj to the list nclist we can us nclist.count()to return the number of items in the list nclist and nclist.object(i) to return a reference to the object at index i in the list nclist.

We can put these commands together to change properties of the connections. For example,

for i = 0, nclist.count()-1 { nclist.object(i).weight = 0.006 }

will change the weights of the two synapses syn[0] and syn[1] to 0.006. This is an advantage when using many synapses.

C.2.D Viewing the simulation

Time plots allow you to see exactly what happens to a variable vs. time at a single point in the . To see what happens at all points in a section (or a group of sections), you can use a space plot. In order to generate a static graph of a variable vs. both time and space you need to produce a 3-D graph. NEURON gives you the next best thing: a movie-like graph called a space plot. This dynamic graph will plot a variable (e.g., voltage) vs. space for each time step in the simulation. After loading your hoc code, display a PlotShape object either by clicking on “menu>>graph>>Shape plot” or by typing 

objref sp

  

  
  
  
  
  sp = new PlotShape()

Shape plot is a powerful graphical interface to view a running simulation.

From the new graph window, you can select the menu item (with the right mouse button) Space Plot. By default, voltage is the variable to plot, but you can change this with the Plot What? menu item (e.g., to ina or m_hh). To create the space plot graph, you need to select a section to include in the space plot by clicking the left mouse button at the beginning of the section (in the schematic picture), dragging the mouse across the section you want to plot (while holding the mouse button down), and releasing the mouse button when you have covered the sections you want to plot. A line will appear from where you first clicked the mouse button to the current location of the pointer. When you release the mouse button, the sections you selected will be highlighted in colour, and a new window with the space plot will be opened. Press the Init & Run button in the RunControl window (or type oc>run() in the command prompt window) to see the space plot in action.


Right click on the plot and select Shape plot option at the bottom of the menu. A voltage color map will appear on the plot window by default between -80 and 40. Run the simulation again and notice that the changes in voltage are represented by changes in the shape colors.

But with fast computers, the simulation may run too fast to note the details. Therefore, we will increase the temporal resolution of the simulation by changing dt to be 10 times smaller than (or even 100 times smaller than) it’s current value and run again.

Another way to reduce simulation speed Change dt back to its original value and change nseg for all the compartments by typing:

forall nseg = int(L + 1)

which tells NEURON to set a the number of compartments per section (nseg) to be equal to their length (e.g. section length 100.1 μm will result in 101 compartments). Does the simulation run slower? Why?
